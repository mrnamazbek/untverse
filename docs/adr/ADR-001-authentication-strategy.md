# ADR-001: Стратегия аутентификации и авторизации

## Статус
Принято (Accepted)

## Контекст
Платформа подготовки к ЕНТ требует надежной, безопасной и удобной системы идентификации пользователей трех основных ролей: `student` (ученик), `teacher` (преподаватель) и `admin` (администратор). Аутентификация должна поддерживать работу через Web SPA (Next.js) и API (FastAPI), а в перспективе — мобильные клиенты и Telegram-бота.

## Решение
1. **Хеширование паролей**: Используется алгоритм `Argon2id` (с обратной совместимостью на `bcrypt`), обеспечивающий устойчивость к атакам перебором на GPU.
2. **Токены доступа и обновления**:
   - `Access Token`: Короткоживущий JWT (15–30 минут), содержит `sub` (ID пользователя), `role`, `exp`. Передается в заголовке `Authorization: Bearer <token>` или безопасной куке.
   - `Refresh Token`: Долгоживущий токен (7–30 дней), сохраняемый в базе данных с возможностью отзыва (session revocation).
3. **Хранение в браузере**:
   - Для веб-клиента токены передаются через безопасные `HttpOnly`, `Secure`, `SameSite=Lax` куки для защиты от XSS-уязвимостей.
4. **Авторизация (RBAC)**:
   - Декораторы и зависимости FastAPI (`get_current_user`, `require_role(["admin", "teacher"])`) централизованно проверяют права доступа к ресурсам.

## Последствия
- Положительные: Высокий уровень защиты от XSS/CSRF, легкая масштабируемость на мобильные приложения, возможность мгновенного отзыва сессий.
- Отрицательные: Необходимость механизма ротации токенов на стороне клиента.
