# ADR-003: Реляционная схема данных и стратегия индексирования

## Статус
Принято (Accepted)

## Контекст
Платформа накапливает большие объемы данных активности: попытки прохождения тестов, ответы на отдельные вопросы, транзакции начисления опыта, ежедневные стрики и логи интервального повторения. Хранение критических данных в виде неструктурированного JSON снижает скорость аналитики и нарушает целостность.

## Решение
1. **Нормализация**:
   - Четкие реляционные связи (1:N, N:M) с каскадным удалением или `SET NULL` где требуется.
   - Специфические поля настроек (например, варианты ответов или тест-кейсы) типизируются строго, поддерживая JSONB в PostgreSQL и валидацию Pydantic.
2. **Индексация**:
   - `users(email)` — UNIQUE B-tree.
   - `quiz_attempts(user_id, quiz_id, created_at DESC)` — составной индекс для быстрых выборок истории пользователя.
   - `quiz_answers(attempt_id, question_id)` — быстрый поиск деталей попытки.
   - `user_profiles(xp DESC, total_points DESC)` — индекс для лидербордов и пагинации топа учеников.
   - `streaks(user_id)` — UNIQUE индекс.
   - `spaced_repetition_cards(user_id, next_review_at)` — для генерации ежедневной очереди повторений.
3. **Миграции**:
   - Все изменения схемы фиксируются версионными миграциями `Alembic`.

## Последствия
- Высокая производительность сложных агрегатных и аналитических запросов без Full Table Scan.
- Защита от коллизий данных и надежная ссылочная целостность.
