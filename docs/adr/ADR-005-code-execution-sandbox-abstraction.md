# ADR-005: Архитектура безопасного исполнения и проверки кода

## Статус
Принято (Accepted)

## Контекст
Платформа содержит интерактивные задачи на программирование (Python 3) и запросы SQL. Прямое неизолированное выполнение студенческого кода в основном процессе FastAPI представляет критическую угрозу безопасности (RCE, утечка переменных окружения, исчерпание памяти/CPU).

## Решение
1. **Интерфейс абстракции `CodeExecutionService`**:
   - Единый контракт `execute(code: str, test_cases: List[TestCase], timeout: float) -> ExecutionResult`.
2. **Многоуровневая защита**:
   - **Уровень 1 (AST-анализ)**: Запрет опасных узлов синтаксического дерева (`import os`, `import subprocess`, `eval`, `exec`, `open`, `__import__`, манипуляций с `globals`/`locals`).
   - **Уровень 2 (Процессная изоляция)**: Выполнение в отдельном изолированном подпроцессе с жесткими лимитами по CPU, оперативной памяти (50MB) и времени (2.0 секунды).
   - **Уровень 3 (Готовность к контейнеризации)**: Возможность бесшовного переключения на удаленный gVisor/Docker runner при масштабировании инфраструктуры без изменения сигнатур сервиса.

## Последствия
- Полная безопасность сервера приложений от злонамеренных скриптов.
- Мгновенная обратная связь для ученика с детализацией по каждому тест-кейсу (Input, Expected Output, Actual Output, Passed).
