# ADR-004: Событийно-ориентированный движок геймификации

## Статус
Принято (Accepted)

## Контекст
Геймификация не должна быть размазана по кодовой базе (например, вызов начисления XP прямо из эндпоинта отправки ответа на вопрос). Это приводит к спагетти-коду, уязвимостям к гонкам и сложности тестирования.

## Решение
1. Централизованный `EventDispatcher` публикует строго типизированные события:
   - `QuizCompletedEvent(user_id, quiz_id, score, total_questions, time_spent)`
   - `LessonCompletedEvent(user_id, lesson_id)`
   - `CodingTaskCompletedEvent(user_id, task_id, passed_all)`
   - `DailyActivityEvent(user_id, activity_type)`
2. `GamificationService` выступает единым обработчиком:
   - Создает атомарную запись в `XpTransaction`.
   - Пересчитывает текущий уровень и ранг.
   - Проверяет критерии разблокировки достижений (`AchievementChecker`).
   - Инкрементирует или восстанавливает стрик (`StreakManager`).
   - Обновляет прогресс ежедневных и недельных квестов.

## Последствия
- Чистая изоляция обучающего домена от игровой механики.
- Легкость добавления новых наград и сезонов без правки логики квизов.
